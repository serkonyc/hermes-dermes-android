# Neon Runner 3D — план модернизации (v4.17)

## Диагноз текущего v2

- Рендер: fake-3D на canvas 2D (`project()` + `poly()`), спрайт-персонаж из 9 PNG,
  объекты — нарисованные "коробки" из 3 граней. Движение выдаёт псевдо-3D сразу.
- Логика (3 полосы, jump/roll, спавн, коллизии, свайпы, difficulty ramp) — здоровая, портируется as-is.
- Свет/тени/глубина/материалы отсутствуют физически — это потолок 2D-подхода.

## Решение: Three.js в том же WebView

Ничего из Android-слоя не меняется (RunnerActivity остаётся WebView-обёрткой).
Меняется только содержимое `assets/web/`.

### Почему Three.js r147 (UMD), а не современная ESM-сборка

WebView грузит `file:///android_asset/` — Chromium блокирует ES-модули с file:// (CORS).
r147 — последняя ветка с классическими `<script>`-бандлами (`three.min.js` +
`examples/js/postprocessing/*`). Один файл ~620 КБ + bloom-аддоны ~60 КБ, офлайн, без import map.
Апгрейд версии — только при переходе на asset-сервер или base64-инлайн модулей; не нужно.

### Что даёт "проработанное 3D"

1. **Настоящая сцена**: PerspectiveCamera за игроком,PerspectiveFog, z-буфер,
   движение камеры (follow + наклон при смене полосы + kick при смерти).
2. **Процедурный мир, без внешних моделей** (главное правило: никаких .glb, всё из примитивов):
   - дорога из сегментов с эмиссивными неоновыми кромками, штрихи полосы — инстансы;
   - pylons/арки вдоль трассы — InstancedMesh, lights-эмиттеры;
   - city-blocks на горизонте — инстансированные боксы разной высоты;
   - synthwave-солнце и звёзды — как сейчас, но в skybox-слоях с параллаксом камеры.
3. **3D-раннер вместо спрайта**: стилизованный low-poly из боксов (торс/голова/4 конечности),
   скелетная анимация через синусы (бег, прыжок-группировка, подкат-слэм).
   Материал: dark + эмиссивные циан-линии — "неоновый бегун", читается на любой скорости.
4. **Пре-рендер materials**: MeshStandardMaterial + 2 источника света
   (key-циан сверху, rim-фиолет сзади) + emissive у препятствий.
   Препятствия — свои формы: low block (жёлто-фиолетовый блок с шевронами),
   bar (перекладина-портал), wall (красная стена-щит с рамкой) — читаемость типа с дальности.
5. **Post-processing**: UnrealBloomPass (half-res, threshold ~0.8) — неон начинает светиться;
   vignette через дешёвый fullscreen-квад; chromatic aberration не делаем (цена/риск на Adreno).
6. **Сок**: GPU-частицы (Points) за игроком — speed streaks; dust при приземлении;
   взрыв при смерти; тряска камеры вместо translation-шейка канваса; speed lines FOV-warp
   (FOV растёт со скоростью 70→86).

### Что остаётся нетронутым

- Вся game-логика v2: state machine, spawn/collide/difficulty, localStorage best,
  свайп-инпут (touch/keyboard), портретный аспект.
- RunnerActivity, манифест, билд-пайплайн.

## Производительность (Fold, Adreno)

- DPR cap 1.75, bloom на half-res, всё статическое — InstancedMesh (1 draw call на класс).
- Бюджет: <30 draw calls, <10k треугольников в кадре, 60 FPS целимся, 30 — floor.
- Тест-прогон: headless Chromium (уже в пайплайне мокапов) + профиль кадров;
  на телефоне финальная сверка — последняя стенда как всегда.

## Этапы

1. **Скелет**: three.min.js r147 + bloom в assets/web, порт S/state/collide/spawn на
   реальную камеру, серые кубы вместо спрайтов. Играбельно, 60fps.
2. **Мир**: материалы, свет, дорога/pylons/город инстансами, fog, skybox-солнце.
3. **Персонаж**: low-poly раннер + анимации бега/прыжка/подката, тень-круг пропал —
   real shadow не берём (dithered blob shadow-дешевле и стабильнее).
4. **Сок**: bloom-тюнинг, частицы, камера-кики, FOV-warp, смерть-слоумо (0.4x на 0.5s).
5. **HUD/меню** в design-токенах приложения (obsidian/циан/фиолет, моно-ширина),
   экраны menu/over поверх 3D, а не канвас-текстом.
6. **Финиш**: тюнинг производительности, bump до v4.17.0, release.sh, коммит.

## Риски

- file:// + WebGL: стандартно работает в WebView на Android 15 (проверим на этапе 1 сразу).
- r147 — ветка 2023 года; для нашей сцены функционально без разницы, фиксируем в коммите.
- Bloom на Adreno в WebView: если fps<45 на Fold — отключаем bloom одной строкой (S.bloom=false),
  сцена должна выглядеть законченной и без него (fallback заложен в этап 2).
